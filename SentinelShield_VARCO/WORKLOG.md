# 센티넬 보호막 스킬 모션·이펙트 — 작업 기록 (VARCO 작업 폴더, Assets 밖, Unity 미적용)

## 1. 요청과 범위 (2026-10-14)
- 센티넬(`AmethystSentinel`, 수호자·epic)의 보호막 스킬: 웅크리기 → 보호막 생성·유지(LOCK 에 따라 진해짐) → ①기한 안에 못 깨면 폭발(레미 피해) / ②깨면 녹아내림 + 스턴(노란 별). 제작·미리보기까지, **사용자 컨펌 전에는 Unity 에셋·Animator·프리팹·전투 코드를 바꾸지 않는다.** 커밋 안 함, 기존 센티넬 모션·원본 덮어쓰기 없음(새 폴더 `SentinelShield_VARCO/`).
- 이번 단계 = 핵심 포즈(기본 → 웅크림)와 보호막 농도 비교(0/25/50/75/100%)까지. 방향 확인 뒤 두 분기 GIF·폭발·녹아내림·스턴 별을 만든다.

## 2. 최신 코드로 확인한 사실 (2026-10-14, 수치 변경 없음)
- `Enemy.cs`: `GuardianShield = 5`, `GuardianChargeActions = 2`, `StunActions = 1`. `StartCharge()` = 보호막 5 + 기한 2. `AdvanceCharge()` 가 수호자 행동마다 기한을 1 줄이고 0 이 되면 강공격 9 + 남은 보호막 제거. `TakeDamage` 에서 보호막이 0 이 되면 기한 취소 + 스턴 1행동. `IsStunned` = 막을 행동 남음 또는 직전 행동이 스턴(눈송이처럼 다음 행동 전까지 표시). 소환 부활 시 보호막·기한·스턴 초기화.
- `CombatManager.cs`: `piecesPerBag = 7`. 실제 고정(`HandlePieceLocked`)마다 `piecesPlaced++`, 7개째에 `EndPlayerTurn`(누적 피해를 타겟에게 한 번 정산 → 보호막이 먼저 받음 → `piecesPlaced = 0` → `EnemyTurn`). `EnemyTurn`: 빙결·스턴이면 `continue`(스킬 카운터·기한 그대로), 능력 턴이면 `StartCharge`, 준비 중이면 `AdvanceCharge`(기한 0 이면 강공격 `hpDamage`). Top Out 은 `EndPlayerTurn` 을 강제로 호출(가방이 덜 찼어도 수호자 행동 1회 진행). Hold·이동·회전은 `piecesPlaced` 에 영향 없음.
- 행동 종류(`NotifyAction`): 능력 턴 = `Skill`(보호막 생성), 기한 > 1 = `Charging`, 기한 == 1 = `StrongAttack`(폭발 시점).
- **보호막 생성부터 폭발까지 실제 허용 LOCK = 14번(가방 2개 × 7)**: 생성은 가방 끝(7번째 고정) 적 턴에서 → 다음 가방 1~7번째 고정, 7번째 정산 후 수호자 행동 1(기한 2→1) → 그다음 가방 8~14번째 고정, 14번째 정산(보호막 피해) 후 수호자 행동 2(기한 1→0 = 폭발). 생성을 일으킨 7번째 고정은 충전 횟수에 넣지 않음. 보호막 피해는 정산(7·14번째 고정)에서만 들어가고 독은 수호자 행동 시작에 적용.
- 충전 진행도(상태에서 계산, 이벤트 누적 아님): `p = ((2 − ChargeActionsLeft) × 7 + piecesPlaced) / 14`. 고정 1번마다 정확히 1/14(≈7.1%) 증가(중복 증가 없음), 25% ≈ 3.5번째, 50% = 7번째, 75% ≈ 10.5번째, 100% = 14번째. 보호막 HP 와 무관(피해를 받아도 초기화 안 됨).
- 빙결·스턴으로 막힌 수호자 행동은 기한을 세지 않아 폭발이 7고정 늦어짐 → 같은 식이면 `ChargeActionsLeft` 는 그대로이고 `piecesPlaced` 만 0 으로 돌아가 충전 표시가 그 가방 시작 값으로 되돌아감(실제 기한과 어긋나지 않음). Top Out 으로 가방이 덜 찬 채 정산되면 수호자 행동이 진행돼 표시가 위로 점프함. **전투 규칙을 바꿀 필요는 없음**(표시를 상태에서 읽기만 함). 단, 빙결 때 표시가 내려가는 모습이 싫으면 선택지가 있음(보고 참조).

## 5. 규격
- 캔버스 144x104(이전 센티넬 공격과 같음), 발 기준점 (72,94), 피벗 (0.5, 0.0962), PPU 75.6, 도트 1칸 = 텍스처 2x2px 위주 → 화면 4px(몬스터 2.00배 × 2x2). 본체는 투명 PNG 알파 0/255, 팔레트는 원본 22색만.

- 보호막(`tools/shield_art.js`): 본체와 **별도 두 층**(면 `Shield_fill.png`, 테두리 `Shield_rim.png`, 144x104 투명 PNG, 2x2 블록 격자). 초타원 돔(초타원 지수 2.6, 바닥 평평) 폭 43블록 = 86px(화면 172px) 높이 36블록(화면 144px), 웅크림 유지 실루엣에 좌우 3블록·위 4블록 여백으로 맞춤 → **충전 중 크기·위치 고정**. 면 = 방사형 보석 면 + 면 모서리선(센티넬 수정 팔레트 #3C1668~#EBA5F9), 테두리 = 외곽 한 겹(왼쪽 위 밝게·오른쪽 아래 어둡게) + 얇은 점선 룬 테두리 + 바닥 선, 작은 장식 없음.
- 농도 = 아트를 바꾸지 않고 층별 알파: 면 α = 0.20 + 0.80·p, 테두리 α = 0.60 + 0.40·p (p = 충전 진행도 0~1). 0% 에서 안쪽 센티넬이 보이고 100% 에서 완전 불투명.
- 게임 화면 합성(스테이지 10: 애벌레 · 센티넬 · 여왕, 센티넬 발 화면 (1574,259)): 보호막 화면 영역 [1486,119]~[1658,263] 폭 172px. **여백**: 여왕 왼쪽 가장자리까지 54px, 애벌레 오른쪽 가장자리까지 72px, HP바 위쪽(y 268)까지 5px → 이웃·HP·SKILL UI 를 가리지 않음. 맨 위 y 119 로 화면 위쪽에서 잘리지 않음.
